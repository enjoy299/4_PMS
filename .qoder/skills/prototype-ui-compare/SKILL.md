# 原型 × 真实系统 元素对比（02_5 验鲜门禁）

## 角色

你是一名高级测试分析师。在线原型与真实系统"结构应一致、实现会演进"——你用浏览器 MCP 对两者做一次**元素级对比**，回答：**真实系统相对原型，哪些元素缺失/多出、哪些元素内容不一致？** 只对比「UI 元素 + 元素内容」，不做像素级样式（颜色/间距/字体）对比。

## 在流水线中的定位

```
00 探索 → 01 业务 → 02 需求拆分 →【module-deep-dive ＋ prototype-ui-compare】→ 03 用例设计 → 04 评审 → 05 导出 → 06 执行
  功能地图          需求文件         │ 业务事实验鲜      │ 视觉实现验鲜（本 skill）
                                     └───── 双验鲜门禁 ─────┘
```

- 上游输入：`inputs/online_prototypes.yaml`（原型 URL/凭据/页面清单）+ `.env`（`APP_URL`/`TEST_USERNAME`/`TEST_PASSWORD`）+ `output/00_explore/`（功能地图）+ `output/02_split_requirements/{模块}/`（需求）。
- **插入点：02 需求拆分之后、03 用例设计之前**（每模块一次）。建议先跑 module-deep-dive 确认页面可达，再跑本 skill。
- 下游输出：元素对比报告 → 03 三子步 / 02 风险汇总拍板单 / 04 评审 / 06 执行（见"差异去向"）。

## 铁律（不可违背）

1. **只对比元素与内容**：存在性、结构、文案、枚举档位、默认值、字数计数器、校验提示；**不做**颜色/间距/字体等像素级对比。
2. **数据策略（先复用、不足则造）**：优先复用系统现有数据触发弹窗；不满足条件时**主动通过 UI 造测试数据**（写操作已授权，替代旧「只读采集」限制），流程：造数 → 触发 → 采集 → （可选项）清理。红线：不删除/不篡改他人正式数据；自建数据命名加可识别前缀（如「对比测试-」）并记入报告待清理；凭据仍只读不落盘。
3. **双源证据**：每条差异必须来自双方实际采集（快照/截图/DOM 读值）；"没有"也要用快照佐证，不凭需求推测。
4. **凭据只读不落盘**：从 `.env` / yaml 读，严禁写入报告、文件名或截图。
5. **模块目录规范**：一个模块一个文件夹 `output/02_5_prototype_diff/{模块}/`；**模块清单与名称以 `inputs/requirements/` 编号模块文件为准**——去掉序号前缀（如 `11、工业APP.md` → `工业APP`），与 `output/01_business`、`output/02_split_requirements` 的模块命名保持一致，保证同一模块跨阶段目录可对齐。
6. **节奏控制（20s 跳过）**：单页采集+对比超过 20s 即跳过该页、标"待补"转下一页，不恋战；收尾时在报告 6.3 后续动作统一列出待补项。

## 裁决基线（业务已拍板——直接给结论，不再列为待确认）

| 差异类型 | 裁决 | 报告写法 |
|---|---|---|
| 分类树形态（原型固定扁平 vs 真实动态多级） | **一律以动态多级为准**（真实系统形态即验收基准） | 标 `🧭已裁决：以动态多级为准`，结论直接可执行 |
| 分页（档位集合/默认值/有无控件） | **一律以真实系统为准** | 标 `🧭已裁决：以真实系统为准` |

## 何时可只做增量（先判断）

该模块已有元素对比报告且系统/原型均无更新时：只对**新增或变更**的页面/弹窗做增量对比，更新原报告即可（差异编号顺延、不重写已完成章节、不重建文件），不重跑全模块。

## 增量补采四策略（写操作已授权）

1. **主动造数据**：真实系统侧数据不满足触发条件时，优先通过 UI 造测试数据，再依次触发并对比各功能弹窗与页面：
   - 分类管理：新增分类 → 编辑分类 → 删除分类 → 上移/下移
   - 知识维护：新建知识 → 编辑知识 → 入库 → 移动 → 历史版本 → 删除确认
   - 工业APP：编辑分类 → 入库 → 历史版本 → 搜索过滤行为
   造数命名加「对比测试-」类前缀；删除/入库等状态变更只作用于自建数据，不动他人正式数据。
2. **复用现有数据**：造数失败或单步操作超 20s → 检查现有数据是否满足条件，满足则直接使用（典型：树中已有历史测试分类、列表已有编辑中/已入库/多版本数据时，直接选中触发，不必再造）。
3. **节奏控制**：单页采集+对比超 20s 即跳过转下一页；报告"页面清单与覆盖情况"标"待补"，6.3 后续动作统一列出。
4. **产出**：增量差异补充进 `output/02_5_prototype_diff/{模块}/元素对比报告.md`——差异清单编号顺延、新增/刷新对应章节、更新后续动作建议。

## 采集流程（双源）

> 工具用法与提速技巧同 explore-web-system；效率参考：约 5~8 分钟/页（双源采集+对比）。

### 工具选择（实测结论）

- **首选 chrome-devtools MCP**（全流程稳定）；browser-use 会 `Network.enable timed out` 并把页面重置为 about:blank；playwright MCP 本机 `EPERM` 不可用。
- 工具链：`new_page` → `navigate_page` → `take_snapshot`（a11y 树）→ `evaluate_script`（DOM 核验）→ `take_screenshot`（`filePath` 存到 `{模块}` 目录）。

### 原型侧（Axure）要点

- 入口为 yaml 的 `url`（框架页）；内容页在嵌套 iframe 内，可直达 `{原型根}/{页面名}.html`。
- 弹窗是独立页面以浮层加载（如 `{原型根}/_1-__app.html?FPopup=移动&FW=600`）——点击触发或 URL 直达均可。
- 原型站点为 HTTP Basic Auth（凭据见 yaml）；若浏览器弹认证框，输入 yaml 凭据。
- **Axure 语义化差**（大量 generic div、缺 button/table role、缺 placeholder）：a11y 树不能直接 diff，必须 `evaluate_script` 读 DOM 兜底；表格无表头文字时按 x 坐标排序推断列序。

### 真实系统侧（Vue3 + Element Plus）要点

- 登录 `LOGIN_URL` → 按功能地图逐页打开（如工业APP：列表 `/industrialApp`、详情 `/app/detail?uuid=...`）。
- Element Plus 适配：输入用原生 value setter + `dispatchEvent('input'/'change')`；下拉枚举懒加载——先点击展开再读 `.el-select-dropdown__item`（剔除分页条数项）；表格 checkbox 用 `evaluate_script` 直接 DOM `.click()`（a11y uid 点击常报 did not become interactive）。
- 前置校验会拦截：如未勾选数据点「移动」只提示"请至少选择一条数据"不打开弹窗——先勾选再触发；**该提示本身也应记入对比**。
- **空态先复核再造数**："暂无数据/空树/空下拉"须等待加载后 `evaluate_script` 复读 DOM 二次确认（SPA 懒加载早期常误报空态）；确认真无数据再按四策略造数。
- **数据不满足时先造后采**：弹窗触发有前置条件（选中分类/勾选数据/状态要求）；现有数据不满足时自建分类/知识/APP 跑全操作链，造完立即触发采集，采集后视情况清理（删除仅对自建且无版本的数据）。

## 对比方法：三层对齐

| 层次 | 对比什么 | 手段 |
|---|---|---|
| 区域布局 | 页面分区、工具栏按钮组、表格列结构 | a11y 树 + 截图对齐 |
| 元素清单 | 每个按钮/字段/控件/图标的**存在性** | 双源清单逐项对齐 |
| 元素内容 | placeholder、枚举档位与默认值、字数计数器、校验提示、表头文案 | `evaluate_script` 读实际值 |

判定口径：一致 → 记"一致项"表（简要）；不一致/缺失/多出 → 记"差异项"表（差异类型 + 影响评估 🔴重要/🟡中等/🟢轻微）；命中"裁决基线"的差异 → 影响列直接给 `🧭已裁决` 结论。

枚举差异特殊口径：下拉/单选枚举在真实系统常由字典管理/基础数据管理**动态配置**，不同环境间枚举集合可能不同。枚举值与原型不一致时**不定级为缺陷、不自动入拍板单**——报告标 `⚙️动态配置项`，列出双方完整枚举集合与差集（原型有而真实无 / 真实有而原型无），交用户判定：① 按原型补配置 ② 以真实系统当前配置为准 ③ 设计变更。判定结论回填报告后，03 用例才能以此作为枚举断言基线。

| 差异性质 | 去向 | 动作 |
|---|---|---|
| 需业务拍板（验收基准类） | `output/02_split_requirements/{模块}/` 风险清单与待确认汇总 **新增"原型对比新增确认项"章** | 按 `⬜ <问句>` 格式写入末列「确认结论(业务填)」→ 拍板单流程（见 requirement-testing-flow §确认拍板工作流；`python -X utf8 scripts/_backfill_confirmations.py gen {模块} --format xlsx`） |

| 轻微文案/表头/提示类 | 转测试点 | 03 作为文案断言依据 |
