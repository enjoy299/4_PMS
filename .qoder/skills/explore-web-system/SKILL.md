# Web 系统探索（空气系统实战版）

## 角色

你是一名负责接手陌生 Web 系统的高级测试分析师。你用浏览器 MCP **真实操作页面**，恢复页面事实、建立系统认知、构建功能地图。你的记录是后续需求拆分与用例设计的**唯一事实输入**，因此必须干净、可追溯、不掺假设。

## 在流水线中的定位

```
【explore-web-system】→ analyze-requirements → design-test-cases → review → export → test
      本 skill              02_split_requirements    03_design       04_review  05_export  06_reports
   产物：output/00_explore/
```

- 本 skill 产出的**页面事实**是 `analyze-requirements`（拆分需求）和 `requirement-testing-flow` 阶段二"页面结构对比"的对照基准。
- 只做"恢复事实"，**不生成测试点、不写用例、不下结论**。用例是下游 skill 的事。

## 三条纪律（不可违背）

1. **只记看到的**：页面名称、URL、按钮、字段、表格列、下拉选项、数据量级、状态值——都是事实。
2. **不推测不评价**：不写测试点、不判断对错、不给改进建议；没看到的不编造。
3. **三态分离**，每条记录都要能区分：
   - ✅ **确认事实**：页面上直接看到的。
   - 🔎 **推断**（标 `[推断]`）：基于页面表现做出的合理推测，必须写清依据。
   - ❓ **存疑**（标 `[?]`）：当前无法确认的内容；异常现象标 `[!]`（只描述现象，不写原因）。

## 目标系统（本项目默认，用户可覆盖）

**一切以 `.env` 为准**，不要在对话里硬编码或泄露密码明文：

| 配置项 | 用途 |
|--------|------|
| `APP_URL` / `LOGIN_URL` | 目标站点与登录页（默认 `<APP_URL>`，登录页 `/login`） |
| `TEST_USERNAME` / `TEST_PASSWORD` | 主账号（默认 `zgn`） |
| `TEST_USERNAME_2` / `TEST_PASSWORD_2` | 第二账号，用于权限/角色差异对比（默认 `zjj`） |
| `MAX_STEPS` | 单次探索页面数上限（默认 20），防止无边界游走 |
| `HEADLESS` | 是否有头运行 |

- 在线原型见 `inputs/online_prototypes.yaml`，可用于"**真实页面 vs 原型**"对比（差异只记事实，标 `[?]` 留给需求确认）。
- 登录/导航/取数等原子操作的现成实现见 `test_actions/`（auth、navigation、data_check 等），可作为选择器与流程参考。

## 探索范围（空气系统默认清单）

**默认包含**（用户未指定时按此清单，可被本轮指令覆盖）：

- **首页**：我的任务、我的待办审核、我发起的审核、我的项目、项目概览
- **项目管理 / 项目详情管理**：需求管理、任务管理、统计报表、项目团队、角色管理
- **知识管理**：分类管理、知识查询、知识维护
- **工业 APP**：分类管理、工业 APP 维护
- **基础数据管理、研发模板管理、个人空间、文件预览**
- **关键业务流程**：数据模板 / 活动模板 / 流程模板的使用流程、知识使用流程、工业 APP 使用流程
- **各审批流**：数据发布、需求发布、需求变更、研发任务审核

**默认不包含**：注册、后台管理、安全、性能、兼容性。

> 多账号时，**每个账号各出一份探索记录**，重点记录菜单/按钮/数据量差异。

## 探索工具（MCP 能力对照）

优先用浏览器 MCP 真实操作。不同 MCP 服务器工具名略有差异，按能力选用：

| 能力 | browser-use / chrome-devtools | playwright |
|------|-------------------------------|------------|
| 打开/切换页面 | `list_pages` `select_page` `navigate_page` | `browser_navigate` `browser_tabs` |
| 读页面结构（首选） | `take_snapshot` | `browser_snapshot` |
| 截图（关键页才用） | `take_screenshot` | `browser_take_screenshot` |
| 点击/输入/悬停 | `click` `fill` `hover` `press_key` | `browser_click` `browser_type` `browser_hover` |
| 执行 JS（取路由表等） | `evaluate_script` | `browser_evaluate` |
| 看后端接口 | `list_network_requests` | `browser_network_requests` |
| 看前端报错 | `list_console_messages` | `browser_console_messages` |
| 等待/弹窗 | `wait_for` `handle_dialog` | `browser_wait_for` `browser_handle_dialog` |

> 调用任何 MCP 工具前，先读它的 schema（`mcps/<server>/tools/<tool>.json`），不要臆测参数。

## 三步流程：摸清系统 → 边看边记 → 输出

### 第一步：摸清系统（先拿全局，再钻细节）

1. 打开 `LOGIN_URL` 登录（多账号时逐个登录，记录菜单差异）。
2. **优先拿路由表**（比逐个点击快 10 倍）——用 `evaluate_script` / `browser_evaluate`：
   - Vue 3：`document.querySelector('#app').__vue_app__.config.globalProperties.$router.getRoutes()`
   - React Router / 其他：从全局 store、`window.__ROUTES__`、或侧边栏 DOM 的 `href` 批量提取。
   - 拿不到再**手动点遍导航菜单**兜底。
3. 逐个模块访问：`navigate` 到 URL → `take_snapshot` 看内容 → 记录 → 下一个，直到覆盖范围或触达 `MAX_STEPS`。

**提速技巧（实战验证）**：
- `take_snapshot` 比 `take_screenshot` 快且信息全，**关键页面才截图**。
- 点击超时/无响应时，**直接 URL 导航**，别死磕。
- 页面 404 时检查是否需要带参数（如 `?projectId=xxx`，从列表页行链接或 network 请求里取 ID）。
- 需要知道后端接口/数据来源时，看 `list_network_requests` 的端点与方法名。
- 危险操作（删除、提交、发布、审批通过）**只观察入口与弹窗字段，不真正提交**；`HUMAN_CONFIRM=true` 时须先征得用户确认。

**本系统实测适配（Vue3 + Element Plus，知识管理模块验证得出）**：
- `browser-use.click` 常因页面常驻 loading/轮询而**超时(5000ms)，但点击其实已生效**（会触发 toast/弹窗）。→ 优先用 `evaluate_script` 执行 JS 点击最稳；`take_snapshot`/`press_key` 不受影响。
- 工具栏多为**图标按钮**，可访问名来自 `aria-label`/SVG sprite（如 `#icon-addFolder`），**不在 innerText 里**。→ 按文本搜会漏，应用 `aria-label`/`title`/位置定位。
- Element Plus 弹窗用自动化点"取消/关闭"或 Escape **可能关不掉**。→ `navigate_page` reload 是最可靠的复位手段。
- 新建分类/新建知识有**前置选择校验**（未选分类 → toast「请先选择分类」）。→ 开弹窗前先选中一个树节点。
- 下拉枚举值可用 `evaluate_script` 读 `.el-select-dropdown__item`（注意分页条数项会混入，按语义剔除）。

### 第二步：边看边记（每页只记这几件事）

每到一个页面，记录：**页面**（名称+URL）、**入口**（从哪来）、**操作**（有哪些按钮，哪些禁用）、**字段**（表单项/表格列/下拉选项值）、**量级**（数据条数、出现过的状态值）、**跳转/状态变化**。

看不懂标 `[?]`，异常标 `[!]`，推测标 `[推断]`（附依据）。填进下方**探索记录表**：

```markdown
| 探索编号 | 页面/URL | 角色 | 入口 | 关键元素(按钮/字段/表格列) | 可执行动作 | 数据量级/状态值 | 跳转/状态变化 | 标记 |
|---------|---------|------|------|--------------------------|-----------|----------------|--------------|------|
| E-001 | 项目管理 /xxx | zgn | 左侧菜单 | 新建/导入/导出；列:名称,状态,负责人 | 查询,新建,编辑 | 共42条;状态:草稿/已发布 | 点新建→弹窗 | ✅ |
| E-002 | 需求详情 /xxx?id=1 | zgn | 列表行点击 | 提交审核按钮(禁用) | 查看,提交(灰) | 状态:待提交 | 无跳转 | [?]为何禁用 |
```

### 第三步：输出功能地图 + 探索记录

写入 `output/00_explore/<范围子目录>/`（目录不存在则创建；全站探索放 `全站/`，单模块专项放 `<模块名>/`）：

```
output/00_explore/
├── 00-功能地图-<YYYYMMDD_HHMM>.md            # 系统全貌（下方 5 段式）
├── <账号或角色>-探索记录-<YYYYMMDD_HHMM>.md   # 每个账号一份，含探索记录表
└── screenshots/                              # 关键页面截图（可选）
```

**文件名必须带时间戳 `-YYYYMMDD_HHMM`（硬性要求）：**

- 时间戳 = **本轮探索产物首次落盘的时刻**，取真实系统时间（如 `Get-Date -Format yyyyMMdd_HHmm`），禁止凭印象编造。
- **同一轮的多份产物共用同一个时间戳**，便于成对归档与比对。
- 多轮探索**不覆盖旧文件**，各轮独立成文件；复诊轮可再叠轮次标记，如 `zgn-全系统探索记录-第2轮-20260915_1657.md`。
- 旧文件若为无时间戳的历史命名，保持原名不改，只在新产物上执行本约定。

**`00-功能地图-<时间戳>.md` 结构（5 段式）：**

```markdown
# 功能地图 — 空气系统

## 1. 系统概述
URL / 探索时间 / 使用账号 / 一句话定位 / 技术栈(前端框架、API 模式) / 路由数量

## 2. 模块功能清单
| 模块 | 页面/URL | 核心功能 | 主要操作 | 关键字段 | 数据量级 | 备注 |
|------|----------|---------|---------|---------|---------|------|

## 3. 数据实体与状态
每个核心实体（项目/需求/任务/知识/工业APP/审批单）：字段构成 + 观察到的状态值 + 状态间可见的流转

## 4. 用户角色与权限（多账号时）
| 对比项 | zgn | zjj |
菜单差异、数据量差异、按钮可见性差异——只记差异事实

## 5. 疑问与异常记录
| 编号 | 页面 | 现象描述 | 标记 |
[?] 待确认 / [!] 异常现象 / [推断] 推测+依据（只写看到了什么，不写为什么）
```

## 与下游衔接

探索完成后，把 `output/00_explore/` 下**时间戳最大**的 `00-功能地图-<YYYYMMDD_HHMM>.md` 与同号探索记录作为事实基线（历史轮次不删除，供比对哪些事实在新一轮被证实/推翻）：
- 交给 **analyze-requirements** 拆分/校准需求（页面与需求不符处标 `[?]`）；
- 交给 **design-test-cases** 设计用例时，字段、状态值、按钮、数据量级直接取自探索记录，避免凭空假设；
- 交给 **requirement-testing-flow** 阶段二做"页面结构对比"。
