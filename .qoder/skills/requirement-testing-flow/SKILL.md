# 需求测试标准流程（流水线辅助技能）

## 定位

本技能是 `python run.py pipeline` 流水线的**辅助补充**，提供测试方法论指导：
- 不替代现有命令（analyze/design/review/test）
- 在执行各阶段时提供流程规范和检查清单
- 特别强化"页面对比"环节，避免基于错误假设设计用例

## 核心原则

**先验证，再测试** —— 确保页面实际结构与需求文档一致，避免基于错误假设设计用例。

---

## 阶段一：理解需求

### 1.1 通读需求文档
- 完整阅读需求文档，理解业务背景
- 标注关键功能点、业务规则、约束条件
- 识别前置条件和依赖关系

### 1.2 提取测试要素
- 功能模块列表
- 页面结构描述（按钮、字段、表格、弹窗等）
- 业务流程（操作步骤、状态流转）
- 业务规则（校验规则、权限控制、数据约束）

### 1.3 输出需求理解文档
创建 `XX-需求理解.md`，包含：
- 模块概述
- 功能清单
- 业务规则汇总
- 待确认问题列表（表格**末列固定「确认结论(业务填)」**：待拍板项预填 `⬜ <具体问句>？`，业务就地回填 `⬜` → `✅ <结论>`，与 02 风险清单填法一致）

---

## 阶段二：页面结构对比

### 2.1 打开目标页面
- 登录系统，导航到需求对应的页面
- 截图记录页面全貌

### 2.2 逐项对比

| 对比项 | 检查内容 | 不一致时处理 |
|--------|----------|-------------|
| **页面布局** | 左侧树/列表、右侧内容区、顶部工具栏 | 记录实际布局，更新理解文档 |
| **按钮** | 按钮名称、位置、数量、图标/文字 | 记录实际按钮，标注差异 |
| **字段** | 字段名称、类型、必填/选填、默认值 | 记录实际字段 |
| **表格** | 列名、排序、分页、操作列 | 记录实际表格结构 |
| **弹窗** | 弹窗标题、字段、按钮 | 记录实际弹窗结构 |

### 2.3 对比结果处理

**一致** → 进入阶段三

**不一致** → 
1. 截图标注差异
2. 更新需求理解文档
3. 与产品/开发确认（是需求变更还是实现偏差）
4. 基于实际页面调整测试策略

---

## 阶段三：划分子模块

### 3.1 模块划分原则
- 按功能区域划分（如：分类管理、数据维护、查询统计）
- 按业务流程划分（如：新建、编辑、删除、审核）
- 按页面区域划分（如：左侧树、右侧列表、顶部工具栏）

### 3.2 子模块清单
为每个子模块明确：
- 功能范围
- 涉及页面元素
- 前置条件
- 测试优先级

---

## 阶段四：执行测试

### 4.1 测试顺序：从左到右，从上到下，从外到里

```
┌─────────────────────────────────────────────┐
│  顶部工具栏（筛选、搜索、批量操作）           │  ← 先测
├──────────┬──────────────────────────────────┤
│          │  右侧内容区                       │
│  左侧    │  ┌─────────────────────────────┐ │
│  树/列表 │  │  表格/表单（从外到里）       │ │
│          │  │  ┌─────────────────────┐   │ │
│  (先测)  │  │  │  行内操作按钮       │   │ │  ← 后测
│          │  │  └─────────────────────┘   │ │
│          │  └─────────────────────────────┘ │
──────────┴──────────────────────────────────┤
│  底部（分页、统计信息）                       │  ← 最后测
└─────────────────────────────────────────────┘
```

### 4.2 从外到里详解

**外层** → **中层** → **内层**

| 层级 | 内容 | 示例 |
|------|------|------|
| 外层 | 页面级操作 | 导航、筛选、搜索、批量操作 |
| 中层 | 列表/表格级操作 | 选中行、排序、分页 |
| 内层 | 行内/单元格操作 | 编辑、删除、查看详情 |
| 核心 | 弹窗/详情页操作 | 表单填写、提交、取消 |

### 4.3 每个子模块的测试流程

```
1. 进入子模块页面
   ↓
2. 验证页面加载正常
   ↓
3. 测试查询/筛选功能（从上到下）
   ↓
4. 测试列表展示（从左到右）
   ↓
5. 测试新增功能（从外到里：打开弹窗→填写→保存）
   ↓
6. 测试编辑功能
   ↓
7. 测试删除功能
   ↓
8. 测试特殊操作（导入、导出、审核等）
   ↓
9. 测试边界和异常场景
```

## 阶段五：记录结果

### 5.1 测试记录格式

| 用例 ID | 模块 | 用例标题 | 状态 | 备注 |
|---------|------|----------|------|------|
| TC-知识管理-分类管理-001 | 子模块名 | 简短描述 | PASS/FAIL/BLOCK | 问题说明 |

### 5.2 问题记录
- 截图标注问题位置
- 记录实际结果 vs 预期结果
- 标注严重程度（阻塞/严重/一般/建议）

## 确认拍板工作流（拍板单 → 回填）

**何时用**：模块剩余 ⬜ 较多且散布多份文档（02 风险清单/歧义/缺口/基线 + 03 需求理解）时，逐份就地填易漏且易不一致——用拍板单集中填，一键回填源文档。

**三步命令**（拍板单双格式：`--format xlsx` 生成 Excel 给业务/产品填，默认 md；backfill 按文件后缀自动识别，回填逻辑一致）：

```bash
# 1 生成骨架（平铺该模块全部剩余 ⬜；同编号多源已自动合并为一行）
python scripts/_backfill_confirmations.py gen <模块> --format xlsx   # Excel 版（推荐给业务/产品）
python scripts/_backfill_confirmations.py gen <模块>                 # Markdown 版（对话内 AI 聚类友好）

# 2 业务在「业务结论(业务填)」列填结论后，先预览再回填
#   xlsx：直接填结论文字（✅ 前缀可省；结论含竖线 | 自动替换为 /）
#   md：`⬜ <问句>` 整格换成 `✅ <结论>`（结论禁竖线，含竖线拒绝回填）
python scripts/_backfill_confirmations.py backfill <拍板单.xlsx|拍板单.md> --dry-run
python scripts/_backfill_confirmations.py backfill <拍板单.xlsx|拍板单.md>

# 3 验证计数归零
python scripts/_lint_confirmations.py <模块>
```

**AI 聚类（gen 后，可选）**：gen 已把**同编号多源**自动合并为一行（回填定位分号并入）；AI 只需再合并**跨编号同根**问题——「结论编号」换 C-NN，「回填定位」分号并入同一格（勿改 `文件名:行号#编号` 格式）；按 P0 判据走向 / P1 覆盖度 / P2 可延后分节；每条源 ⬜ 恰好归一个簇，勿重复归属。

**纪律**：
- 拍板单是工作底稿（.md/.xlsx 同规）：不进 git 基线、不进 lint 统计（命名避开「风险清单与待确认汇总/业务全景图」、不放入 test_points/ 目录）
- 结论禁含竖线 `|`（md 拒绝回填，xlsx 自动替换为 /）；同根问题跨文档结论必须一致（回填自动同步）
- 仅扫含「确认结论(业务填)」表头的源文档（探索覆盖状态类 ⬜ 如需求校准报告不收）
- 测试点/用例层的 ⬜ 不手填：拍板上游后重跑 testpoints/testcases 自然消化

## 检查清单

执行测试前复制此清单跟踪进度：

```
需求测试进度：
- [ ] 阶段一：理解需求
  - [ ] 通读需求文档
  - [ ] 提取测试要素
  - [ ] 输出需求理解文档

- [ ] 阶段二：页面结构对比
  - [ ] 打开目标页面并截图
  - [ ] 对比按钮（名称、位置、数量）
  - [ ] 对比字段（名称、类型、必填）
  - [ ] 对比表格（列名、操作列）
  - [ ] 记录差异并确认

- [ ] 阶段三：划分子模块
  - [ ] 列出所有子模块
  - [ ] 明确每个模块功能范围
  - [ ] 确定测试优先级

- [ ] 阶段四：执行测试
  - [ ] 按从左到右顺序
  - [ ] 按从上到下顺序
  - [ ] 按从外到里顺序
  - [ ] 每步操作后截图

- [ ] 阶段五：记录结果
  - [ ] 填写测试结果表
  - [ ] 记录发现的问题
  - [ ] 输出测试报告
```

## 实例参考

以工业APP模块为例：

1. **理解需求**：阅读基础数据管理需求，了解分类管理、APP维护等功能
2. **页面对比**：发现右侧工具栏只有"删除、入库、移动"，没有"新建"（APP通过IAP客户端上传）
3. **划分子模块**：分类管理（左侧树）、APP维护（右侧列表）
4. **执行测试**：
   - 先测左侧树（新增分类、编辑、删除、上移、下移）
   - 再测右侧列表（删除、入库、移动）
   - 从外到里：列表操作 → 行内按钮 → 弹窗操作
